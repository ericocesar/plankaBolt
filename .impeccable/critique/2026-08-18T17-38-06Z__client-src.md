## Anti-Patterns Verdict

**Start here. Does this look AI-generated?**

**LLM assessment.** Yes, in places. The header pill (`border-radius: 50px`, `backdrop-filter: blur(15px)`, sticky top, min-width 400px), the radial-gradient app shell, the white-with-shadow "primary" button with `translateY(-1px)` hover, the global "blur(24px) modals stacked to look like depth" — these are the exact treatments of the "dark + neon + glass" 2024 template, applied to a project whose brand voice in PRODUCT.md is "utilitarian, neutral, calm." Someone glancing at this could absolutely say "AI made it." The category-reflex test fails twice: first-order, a kanban tool could be any color, but a kanban with this exact stack of `rgba(255,255,255,0.05)` borders, 50px pill nav, and 24px-blur modals is the dark+glass reflex in disguise. Second-order, when the user already rejected "avoid AI-decorated," the AI reflex chose the next-most-AI lane anyway.

**Deterministic scan.** Detector CLI bundle is not shipped in this install of the skill (`bundled detector not found`). Counts below come from manual grep, not the bundled detector — treat as indicative.

- `backdrop-filter: blur(...)` in 20+ files: `Header.module.scss:65` (15px), `CardModal:10` (24px), `UserSettingsModal:18` (24px), `ProjectSettingsModal:13` (24px), `AdministrationModal:29/301` (24px/10px), `FormsPane:99` (20px), `List/List.module.scss:171` (12px), `Card/Card.module.scss:53` (10px), `Login/Content.module.scss:96` (24px), `FormBuilder.module.scss:47/251/315`, `FormEditor.module.scss:37`, `Header` and global `styles.module.scss:77/104`. Glassmorphism is the default, not the accent.
- Gradient backgrounds in 16+ places. Note `styles.module.scss:8` app shell `radial-gradient(circle at 50% -20%, rgba(26,201,204,0.2) 0%, rgba(0,0,0,1) 80%), #000000`; `Support.module.scss:5` `radial-gradient(circle at 50% 0%, #1a1a20 0%, #050505 70%)`; and five separate `linear-gradient(... #10b981 ... #059669 ...)` decorative buttons in FormBuilder/FormEditor/Support.
- Pervasive `!important`: 2155 declarations in 203 files (~10.6 per file). The codebase cannot be styled further without more `!important`.
- `outline: none` / `outline: 0` in 20 places, often inside `&:focus` (Comments Add/Edit, List three times, Card, StopwatchChip, DueDateChip, DraggableCard, ProjectCard, two in global). Focus is being killed, not redirected to a custom ring.
- `prefers-reduced-motion`: zero occurrences in the codebase. The decorative hover transforms (translateY, scale) and gradient transitions run for every motion-sensitive user.

The detector's own copy of banned patterns (`border-left/right` colored accent > 1px, `background-clip: text`) returned zero — those particular bans aren't violations here. The bans this codebase breaks are the larger ones: glassmorphism-as-default and the AI-decorated dark+neon lane.

**Visual overlays.** Not produced: no running dev server is reachable in this session (vite + sails.io.js, full stack required) and no viewable `file://` mount was available. Per the critique reference, an unreliable overlay path is reported as a fallback signal rather than fabricated.

## Overall Impression

The functional product is real: drag-drop, real-time sync, markdown, i18n, custom fields, webhooks. Beneath the surface the strategy and the visual layer disagree. PRODUCT.md says "neutral, get out of the way." The CSS says "decorative glass and gradients on every modal." A team using Planka will succeed at their work and not notice the styling — until they resize the window, hit Tab once and lose focus, or sign in with TOTP. The single biggest opportunity is to align the visual layer to the strategic layer: kill the decoration, build a real token layer, restore focus, and let the data shape the chrome.

## What's Working

1. **Domain model is honored in the markup.** `Card → List → Board → Project` survives into the JSX without dressing it up. Card modal exposes attachments/tasks/comments/custom-fields in the right order; markdown lives where it should. PRODUCT.md principle 1 ("the board is the product") is mostly held in structure.
2. **i18n plumbing is real.** Login maps eight backend error strings to translation keys; `useTranslation` is standard; 30+ locales ship. One unmapped Portuguese tab title is the kind of bug an honest lint pass over `menuItem: 'A-Z'` would catch.
3. **Closeable modals are real.** `useClosableModal` returns a wrapper that's actually used across the app (UserSettings, ProjectSettings, CardModal, AdministrationModal, About, Terms). Esc, X, click-outside behave correctly.

## Priority Issues

### [P0] Glassmorphism as default chrome
**What**: `backdrop-filter: blur(4|10|12|15|20|24)px` is applied to header, list, card modal, every settings modal, login panel, board surface. Each picks a different radius and rgba white-tint.
**Why it matters**: PRODUCT.md names "AI-decorated dark + neon" as a hard anti-reference. Glass on an OSS kanban tool reads as 2024 SaaS template and silently fails the design health test. It also slows first paint, blurs text underneath (legibility), and behaves inconsistently across browsers.
**Fix**: Pick one rule (keep glass only on the top app-bar if anywhere) and convert the rest to flat tinted surfaces using design tokens. Remove all `backdrop-filter` from modals.
**Suggested command**: `/impeccable quieter` followed by `/impeccable distill`.

### [P0] No design-token layer
**What**: Only one file (`AdministrationModal/FormsPane/FormBuilder.module.scss:4-13`) defines `$bp-*` tokens; everything else uses raw hex (`#000`, `#050505`, `#1a1a20`, `#fff`, `#10b981`) and `rgba(255,255,255, 0.0x)`. 2155 `!important` declarations exist to fight that.
**Why it matters**: A self-hosted OSS codebase without a token layer cannot be themed, white-labelled, or localised in dark/light. Major team-level customization is blocked.
**Fix**: Promote a single `:root` token file (or use semantic-ui's variable system) with one muted neutral ramp + one accent. Replace raw colors and `!important` walls with token references. Use OKLCH where new.
**Suggested command**: `/impeccable colorize` then `/impeccable extract`.

### [P0] Focus visibility removed across the app
**What**: `outline: none` / `outline: 0` in 20 places, frequently inside `&:focus`, with no replacement focus ring. Examples: Comments/Add.module.scss:36, Comments/Edit.module.scss:30, List.module.scss × 3, Card, StopwatchChip, DueDateChip, DraggableCard, ProjectCard, global styles.module.scss:197/213.
**Why it matters**: Best-effort a11y is declared, but keyboard users (TOTP recovery, drag handles, board switcher) cannot tell where focus is. Power users and screen-reader users are equally affected.
**Fix**: Add a single `:focus-visible` rule on the global layer; remove `outline: none` everywhere. For interactive cards, use a 2px ring at the same accent color.
**Suggested command**: `/impeccable harden` then `/impeccable audit`.

### [P1] Decorative motion ignored everywhere
**What**: `transition: all 0.3s ease` and `transform: translateY(-1px)/scale(1.05)` are scattered (Header, styles.module.scss, Support). Zero `prefers-reduced-motion` handling.
**Why it matters**: Users with the OS "reduce motion" preference still get the hover-lift on every card and button. Plus the `transition: all` declarations are expensive on long lists.
**Fix**: Wrap transitions in `@media (prefers-reduced-motion: no-preference)`. Replace `transition: all` with explicit `transition-property` lists.
**Suggested command**: `/impeccable animate`.

### [P1] Hardcoded "SEGURANÇA" tab in UserSettingsModal
**What**: `UserSettingsModal.jsx:55` uses `menuItem: 'SEGURANÇA'` while the other three panes go through `t('common.X')`.
**Why it matters**: That's the security pane of the settings modal in literal Portuguese to every locale. It's the regression class PRODUCT.md principle 5 ("extensibility is a UI concern") exists to prevent.
**Fix**: Replace with `t('common.security', { context: 'title' })` and add the key to every locale.
**Suggested command**: `/impeccable clarify`.

### [P1] App-shell and Support gradient wash
**What**: Global app background is `radial-gradient(circle at 50% -20%, rgba(26, 201, 204, 0.2) 0%, rgba(0, 0, 0, 1) 80%), #000000`; Support page has its own `radial-gradient(circle at 50% 0%, #1a1a20 0%, #050505 70%)`; the page-level "Global UI Overrides" comment in `styles.module.scss` even mentions "match layout.jpg" — a screen-grab target, not a design system. The neon-emerald buttons (FormBuilder/FormEditor) are green-on-black slop.
**Why it matters**: This is the precise look the user just declared an anti-reference. Each surface that ignores it costs trust.
**Fix**: Replace `radial-gradient` app shell with a flat near-black surface tinted slightly toward the brand hue. Kill `layout.jpg` references; rebuild from tokens.
**Suggested command**: `/impeccable distill`.

### [P2] Pure `#000` and `#fff` neutrals
**What**: `#000`, `#050505`, `#0a0a0a` and `#fff` appear directly across the codebase (raw grep returns 38+ matches in styles.module.scss alone).
**Why it matters**: Pure-black surfaces are harsh on real screens; per the shared design law, neutrals should be tinted toward the brand hue at chroma 0.005–0.01.
**Fix**: Standardize a single near-black, e.g. `oklch(0.18 0.01 240)` and a single near-white, e.g. `oklch(0.97 0.005 240)`. Replace raw values via the token layer.
**Suggested command**: `/impeccable colorize`.

### [P2] Login error mapping is brittle
**What**: `Login/Content.jsx:32-78` switches on literal English backend error strings (`'Invalid credentials'`, `'Email already in use'`, etc.) and falls through to `Failed to fetch` for anything unrecognised.
**Why it matters**: The backend can add a new error class tomorrow and a user will see raw English with no key. The mapping table also breaks for any localized backend.
**Fix**: Have the backend return stable error codes (`AUTH_INVALID_CREDENTIALS`, etc.) the client maps once. Co-locate that mapping.
**Suggested command**: `/impeccable harden`.

## Persona Red Flags

**Jordan (First-Timer).** Lands at login. Sees a tinted, blurred split-screen panel over a radial-gradient background. Errors are mapped to translated strings only for ~8 known server cases; the moment they hit an unmapped error, the toast reads "common.noInternetConnection" while their deck-light UI says nothing. Recovery codes are stored behind a TOTP setup wizard; no inline help. Will abandon on "weird login" at step 2.

**Alex (Power User).** Wants keyboard through the board: no global `?` menu, no `g b / g c / c` shortcuts, no visible "press / to filter" cues. Drags are mouse-only via `react-beautiful-dnd`. Markdown editor is heavyweight (`@gravity-ui/markdown-editor` 15.x). When focus does land on a card, the card's `outline: none` removes the indicator. Power-user reaches keyboard, looks broken, opens custom field panel and gives up.

**Sam (Mobile User).** No responsive verification here, but the global Header pill drops to `border-radius: 20px` at `< 768px` and the radial-gradient app shell doesn't reflow. Glass on a mobile browser is performance-bad and Safari may degrade. No `prefers-reduced-motion` means hovers (which become taps-to-state on touch) still animate transform.

## Minor Observations

- `@import url('https://fonts.googleapis.com/css2?…')` at the top of `Support.module.scss:1` — a marketing surface that demands two network fonts from Google. FOUT, privacy, no caching guarantee. Either self-host the fonts in `assets/` or remove them; the System UI font stack handles this fine.
- Hardcoded `transform: translateY(-1px)` on the global primary button (`styles.module.scss:30`) plus `box-shadow: 0 4px 14px rgba(255,255,255,0.1)` — exact "AI primary button" silhouette.
- The "Global UI Overrides to match layout.jpg" comment in `styles.module.scss` is the smoking gun: a screenshot-driven restyle hard-coded with `!important`. Layout.jpg isn't a design system.
- `EditUserInformation.jsx:59-62` uses `nameFieldRef.current.select()` for validation feedback — silently focusing+selecting without a visible error message. Acceptable but a step behind inline validation.
- `List.jsx` (and presumably others) silently fall back to `outline: none` for draggable handles — drag handles in `react-beautiful-dnd` need their own keyboard path.
- Stylesheet parses 955 lines of `styles.module.scss` with nested `!important` walls. Should not exist as one file.

## Questions to Consider

- How would the same product look if every chrome decision answered "does this let the board breathe?"
- If you removed every `backdrop-filter`, every `radial-gradient`, and every `!important` simultaneously — what would be left that earns its place?
- What does the Pro-tier surface need that the OSS tier shouldn't pay for visually? Right now both look identical, which is fine, but it means the brand surface has nowhere distinct to go.
- Could the team adopt semantic-ui's `ThemeProvider` (or a thin wrapper) so contributors can theme Planka without forking styles? That makes `styles.module.scss` go away, not just shrink.
- What's the one screen that should be the *most* decorated — login, board, card detail, or empty state? Whichever you pick, make everything else quieter.
